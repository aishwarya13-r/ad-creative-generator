# Ad Creative Generator

## Overview

A web application for creating professional social media ad creatives using AI. Users upload product images, define target audience parameters, and generate Instagram/Facebook ad images with AI-powered design. The application provides a Canva-like interface for e-commerce brands to create engaging ad content without design expertise.

**Status:** MVP Complete ✅  
**Last Updated:** November 12, 2025

## Features

- 📤 **Product Image Upload**: Drag-and-drop or click to upload product images
- 🎯 **Target Audience**: Define age range, gender, and persona for precise targeting
- ✍️ **Ad Copywriting**: Create compelling headlines with character limits
- 🤖 **AI Generation**: Two-step Gemini AI process (analyze product → generate ad)
- 👁️ **Live Preview**: Real-time preview of generated ad creatives
- 💾 **Multi-Format Download**: Instagram Square (1:1), Instagram Story (9:16), Facebook Feed (4:5)
- ✨ **Professional Design**: Canva/Adobe Express-inspired UI with vibrant color scheme
- ⚡ **Fast Validation**: Client and server-side validation prevents errors

## System Architecture

### Frontend Architecture

**Technology Stack:**
- React with TypeScript for type safety and component-based UI
- Vite as build tool and development server
- Wouter for lightweight client-side routing
- TanStack Query for server state management and API caching

**UI Framework:**
- shadcn/ui component library with Radix UI primitives
- Tailwind CSS for styling with custom design system
- Design inspired by Canva and Adobe Express (creative-utility hybrid)
- Typography: Inter (body) and Poppins (headings/display)
- Custom color system with HSL variables for light/dark mode support

**State Management:**
- React hooks for local component state
- TanStack Query for server state and caching
- Form state managed through controlled components
- No global state management library (keeping it simple)

**Key Design Decisions:**
- Single-page application (SPA) with minimal routing
- Component-driven architecture with reusable UI primitives
- Form validation at component level before API submission
- Optimistic UI updates for better user experience

### Backend Architecture

**Technology Stack:**
- Node.js with Express.js for HTTP server
- TypeScript for type safety across frontend and backend
- ESM (ES Modules) for modern JavaScript imports

**API Design:**
- RESTful endpoints under `/api` prefix
- Single primary endpoint: `POST /api/generate-ad` for AI generation
- Request/response validation using Zod schemas
- Shared types between client and server via `shared/` directory

**Data Storage:**
- In-memory storage implementation (`MemStorage` class)
- Simple key-value store using JavaScript Map
- Ad projects stored with UUID identifiers
- No persistence layer (data lost on restart - suitable for demo/MVP)
- Storage interface (`IStorage`) allows easy future migration to database

**Storage Interface Design Rationale:**
- Abstract interface allows swapping storage implementations
- Current in-memory solution keeps deployment simple
- Future database integration (PostgreSQL via Drizzle) prepared but not implemented
- CRUD operations: create, read, update, and list ad projects

**AI Integration:**
- Google Gemini AI via Replit AI Integrations service
- **Two-step generation process:**
  1. **Step 1**: `gemini-2.5-flash` (vision model) analyzes uploaded product image
  2. **Step 2**: `gemini-2.5-flash-image` generates ad creative based on description
- Uses environment variables for API credentials
- Processes product images (base64 data URLs)
- Comprehensive error handling for invalid images
- Prompt engineering for professional e-commerce ad design

**Request Flow:**
1. Client uploads image (validated: ≥100x100px, ≤5MB, JPEG/PNG/WebP)
2. User defines target audience (age, gender, persona) and ad text
3. Data validated against Zod schema
4. **AI Analysis**: Product image analyzed by gemini-2.5-flash for detailed description
5. **AI Generation**: Ad creative generated by gemini-2.5-flash-image using description
6. Project stored with generated image URL (base64 data URL)
7. Response returned to client for preview/download

**Error Handling:**
- Client-side: Image dimension and size validation with toast notifications
- Server-side: Comprehensive validation (format, size, Gemini API errors)
- User-friendly error messages for all failure scenarios
- 400 errors for validation/AI issues, 500 for server failures
